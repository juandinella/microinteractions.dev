## Lift the row, nudge the rest

Press a row and move it: it leaves the list and follows the pointer, sideways too, with a larger shadow. The rows after its old slot move up and close the hole, so the list is one row shorter while you drag.

The gap at the pointer is only a nudge. The two rows beside it move 8px away from it, the next pair 5.6px, then 3.9px: each step is `0.7` times the last, or `8px × 0.7ⁿ` with n counting the steps from the gap. The delay falls off the same way: the two rows beside the gap start together, the next pair 24ms later, then 41ms and 53ms, each wait 0.7 times the last. Equal waits would ripple out like a metronome. A 2px line in the gap shows where the row will land. The gap spreads outward from the pointer instead of the list swapping in blocks. The rule comes from Kubai's post, which also uses it on a dock of icons, with 10px.

The nudge and the slot translation share one `transform`, so a single transition carries both. Only rows at rest wait. A row that is still moving when the gap jumps retargets at once from where it is: with a delay it would stop mid-flight, and a fast drag would queue up.

## Ease-out, no rebound

Every row moves for 250ms on `cubic-bezier(0.23, 1, 0.32, 1)`, an ease-out: it starts at speed, so the rows beside the gap answer the pointer at once, then slows into place. There is no spring, because a list you reorder often shouldn't wobble. On release the lifted row takes the same curve and the nudge is removed, so every row lands together.

## Keep the DOM order until the drop

While you drag, the DOM order doesn't change. The lifted row follows the pointer with `translate` and the others move with transforms. After the drop settles, the script reorders the real nodes and clears every transform in the same frame, with transitions off. Nothing moves on screen, because each row is already where its new position puts it. Reordering on every slot change would swap the box under the pointer mid-gesture.

## Keyboard, touch, and reduced motion

Each row is a button. Space or Enter picks it up, the arrow keys, Home, and End move it, Space or Enter drops it, and Escape puts it back, also during a pointer drag. A polite live region announces the pickup, each move, and the drop, with the position out of the total. Keyboard moves don't animate: a held key repeats too fast, and the announcement and the focus state already say where the row went. A held Space doesn't pick up and drop over and over. Moving focus away drops the row where it is.

On touch the row scrolls the page and the grip lifts it. The button has `touch-action: pan-y` and the grip `touch-action: none`, with a 44px hit area that reaches the row's edge. A finger has to move 10px before the row lifts, a mouse 3px.

Two limits. Rows must be the same height, and the layout is measured once when the drag starts. If the page or a scrolling container moves mid-drag, the gap stops matching what you see, and there is no autoscroll at the edges, which [Drag to select](/drag-select/) adds.

With reduced motion nothing glides: the rows jump to their slots, the two beside the gap part by 8px in place, the line only fades, and the lifted row still follows your hand. While you drag, every row's number shows where it would be after a drop at the gap, so the target never depends on motion. In forced colors mode a lifted row gets a `Highlight` outline.
