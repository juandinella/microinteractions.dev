## Separate the label from its arrow

The slider's value label is always visible. Centered on the thumb, it would overflow the container near either end. So the label and its arrow are positioned separately: the label stops at the edge and the arrow keeps following the thumb.

On every `input` event, JavaScript turns the value into a number from 0 to 1. CSS uses it to move an empty element that mirrors the native thumb, and that element anchors both the label and the arrow.

`justify-self: anchor-center` centers the label on the anchor and shifts it inward when it would overflow. The arrow reads `anchor(center)` on its own, so it stays on the thumb. `anchor-scope` keeps each slider's anchor name local. Browsers missing any of these features fall back to `clamp()`, which keeps the label inside the same bounds.

## Follow the input directly

The label, arrow, and fill have no transition, because any easing would leave the label trailing the thumb. `transition-property: none` keeps it that way when global styles add a duration. Reduced motion needs no fallback since nothing is timed.

The native range input handles the keyboard, including Home and End. `aria-valuetext` gives screen readers the value with its unit, and the visual label stays hidden so the value isn't announced twice. The input is 44px high, and `touch-action: pan-y` lets people scroll the page vertically over it.

## Different values and units

The 128px label fits "Volume 100%". For longer text, change its width and the fallback's `128px` and `64px` terms together, and update `aria-valuetext` along with the visible unit. Test the longest label at both ends, with and without anchor positioning.
