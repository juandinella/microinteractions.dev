## The option opens on the value

A dropdown usually opens below its trigger, so the eye and the pointer travel down to the list. This select opens where they already are: the current option lands on the trigger, its label on the same pixels as the trigger's value. The study started from Linear's dropdowns, where nothing on the page shifts and picking a value feels closer to setting a dial than to opening a list. Base UI's Select and Radix Select do it by default, and so does the native pop-up menu on macOS.

A pixel off reads as a layout shift, so the script lines up the texts, not the rows: the trigger's border moves its text by a pixel. Trigger and options use the same 13px font, so once the centers meet, the baselines do too. The check sits in a 14px gutter before every label, as on macOS, so every label starts at the same x and none shifts when the check moves.

## Press, drag, release

A mouse opens the menu on press, so dragging to another option and letting go picks it in one motion. But the current option opens under the pointer, so a plain click is released on it too, and would re-pick the value and close the menu. The release only picks after more than 10px of movement, the threshold Radix uses. Base UI uses a 400ms timer instead, which a slow click outlasts.

A click that never moved leaves the menu open, and from then on releasing over any option picks it. The highlight follows the mouse with no transition, since a highlight that eases in trails the pointer by a row.

## Cut at the window edge

A long list doesn't fit around the trigger. The menu is cut 8px from the window's edge and the list scrolls, so the current option still sits on the trigger, as in the time zone select of the demo. The cut edge shows an 18px scroll arrow instead of a scrollbar, as on macOS.

When the aligned menu doesn't fit, it opens as a dropdown below the trigger, or above it when there is more room. Three rules send it there: the trigger is within 20px of the window's top or bottom, the cut leaves less than 104px of list, or the current option would sit under a scroll arrow. The menu is a `popover="manual"` in the top layer, so no ancestor's `overflow` can cut it. It is placed in window pixels, so a page scroll that moves the trigger closes it.

## 70ms in, one frame out

The menu fades in over 70ms on `ease-out` and closes in one frame. At 60fps that is four frames (36%, 66%, 88%, 100%), so it still reads as a fade; the stronger curve of this site's longer entrances would reach 76% on the first frame, almost a pop. Nothing scales or slides, as in [the recording of Linear's dropdown](https://x.com/Its_Rishikesh/status/2122752377757307042). Closing at once shows the new value right away, with no old menu fading over it.

## Keyboard, touch, and forms

The keyboard follows the APG select-only combobox: focus stays on the trigger, `aria-activedescendant` points at the highlighted option, and the arrows, Home, End and the Page keys move it. Typing jumps to an option, and on the closed trigger changes the value, as a native select does. A menu opened from the keyboard skips the fade and covers the trigger's focus ring, so the highlighted option gets a 2px ring instead.

Touch opens the menu on tap, so a scroll that starts on the trigger doesn't open it, and always below the trigger, because the finger covers it. The fade is opacity only, so it stays with reduced motion.

With a `name`, a hidden input carries the value, so the select submits with its form. [Gooey radio group](/gooey-radio-group/) and [Edge-aware tooltip](/edge-aware-tooltip/) need none: their native inputs stay in the form. It holds one value: groups, disabled options and multiple selection are what Base UI's Select adds.
