## Two labels in one grid cell

Both labels sit in the same CSS Grid cell with `grid-area: 1 / 1`. A grid cell sizes to its largest item, and a label at `opacity: 0` still takes up space, so the button fits the wider label in either state and its width never changes. Nothing is measured with JavaScript.

On hover, the current label slides down and fades out while the next one slides in from above. A 5px blur softens the moment they overlap. All three properties share an ease-out curve, so the swap answers the pointer right away and slows as the new label lands. The swap takes 220ms and the return 160ms, because someone leaving the button has already moved on. Both durations come from the same `--swap-state` variable that drives the labels. Because these are transitions, leaving mid-swap reverses from wherever the labels are.

Pressing scales the button to 0.97, whether the press comes from a pointer or from Space on a focused button. Keyboard focus shows the second label at once, with a focus ring. With reduced motion, the labels crossfade on the same ease-out curve, without sliding, blurring or the press scale. A linear fade would leave both labels at half opacity halfway through. The curve brings the new label most of the way in early. Screen readers hear one stable `aria-label` while both visual labels stay hidden from them.

## Using the pattern

Replace the sample labels and test the longest one, translations included. Both labels should describe the same action, and the `aria-label` should name that action and contain the visible text. The transition works on a `<button>` for actions and on an `<a href="…">` for links.

The exported code swaps on hover and keyboard focus, which touch screens don't have. Keep the action on the first tap there. If the second label says something people need before acting, show it next to the control.
