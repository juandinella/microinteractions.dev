## One line, one transform

There is a single line at the bottom of the list. When a tab is chosen, the script measures the tab with `getBoundingClientRect()` and writes its position and width into one transform: `translateX()` to get there and `scaleX()` to match its width. A CSS transition takes it there in 250ms.

A transition can be interrupted. Choose another tab before the line arrives and it turns from where it is, without jumping back to either end. It keeps the position but not the speed, so after the turn it starts again from the fast start of the curve.

## Why not a view transition

Haz built these tabs with view transitions. Each tab has its own underline, only the selected one carries a `view-transition-name`, and the browser morphs the old box into the new one without measuring anything. A tab chosen mid-move breaks it, though. The document runs one view transition at a time, so the new one cancels the old: the line jumps to where it was headed and only then leaves for the new tab. Waiting for the running one to finish avoids the jump, but then the line reaches the new tab late. Any other view transition on the page, such as a route change, would cancel it the same way.

## Bold without layout shift

Each label shares a grid cell with a hidden copy of itself in bold, an `::after` that takes its text from `data-text`. The cell is always as wide as the bold version, so turning a label bold moves nothing: the other tabs, the counts, and the line stay where they were.

The weight switches at the click. Interpolating it on the variable font looked like a jump followed by a drift: the curve made it almost bold in the first frame, and the letters kept sliding as their widths changed. Crossfading a bold copy doubled the letters halfway. The label answers the click, and the line shows the way there.

## Keyboard, touch, and reduced motion

The list is one Tab stop, and the next Tab goes into the panel. The arrow keys, Home, and End move focus and the selection together, and the line moves without animating, since a held arrow key repeats faster than the line travels. A screen reader hears each count as "5 studies". Before the script runs, the selected tab draws its own underline, so the page never shows the line in the wrong place.

Each tab's hit area is 40px tall for a mouse and 44px for touch. When the tabs don't fit, the list scrolls sideways and fades the edge with more tabs. With reduced motion, the line moves to the new tab without animating. The selected tab is also bold, so the state doesn't depend on color.
